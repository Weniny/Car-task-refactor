## 已确认的问题

1. **完整显示层与抽样规划输入不一致。** 785 帧地图中有 776 帧在原规划读取范围内超过 2000 个占用格，最多 3996 格。occupied_grid_cell_centers 默认隔点抽样到最多 2000 个，删除了约一半碰撞占用格。这是一个真实的完整性问题，可造成错误空隙和逐帧可行性变化；尚不能将所有停顿都单独归因于它。
2. **旧绿线未清除。** 规划失败只发停车请求，没有发布空 Path，RViz 继续画上一条路径，而障碍层继续更新。停车期间大量重叠属于这种旧路径叠加。
3. **新路径也有几何重叠证据。** 162 条新发布路径中，10 条与最近录制地图在地图时间戳 TF 下重叠；改用地图接收时刻 TF 后也有 11 条重叠，不能仅归咎于显示时间差。原包并未记录每次规划的完整内部快照，不能宣称这就是同一时刻内部规划器放行的碰撞路径。
4. **坐标转换时间和栅格面积存在缺口。** 原回调将带时间戳的 body 栅格用最新 TF 转入 map，再将每个占用格只作为中心点投影，可能产生时差偏移和栅格重采样空隙。

## 已修复并部署的范围

新增隔离入口 `rebuild_navigation_replan_radius120_050_030_obstacle_v2.launch.py`，默认适配器关闭，尚不作为已验收实车入口：

- complete_costmap_validation=true 时保留全部占用格，不再按 2000 格抽样；读取范围覆盖代价地图的前后及横向范围。
- 按地图 header.stamp 查询 TF，拒绝缺失时间戳；无法查询该时刻变换时停车，不改用最新变换冒充。
- dynamic_obstacle_cell_size_m=0.05，按旋转栅格的保守面积覆盖目标格，避免只投影中心造成漏格。
- 路径发布前，用同一完整障碍快照按 2.5 cm 间距复核所有路径段；不通过则 OUTPUT_PATH_COLLISION 并停车。
- 无路/输入无效时发布空 Path 清除绿线；控制器收到空 Path 后清除几何和时间缓存、重置控制器，避免依赖消息先后顺序继续使用旧路径。

旧入口默认关闭完整地图新策略；控制器空路径清理和明确无效路径停车属于共享修复。没有缩小原障碍膨胀、删除 Safety，或增加倒车/旋转脱困。
