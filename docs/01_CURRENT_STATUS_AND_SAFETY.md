# 当前状态与安全交接

更新：2026-09-18

## 实车状态

实车测试已冻结。一次静态候选启动执行了：

```bash
ros2 launch rebuild_bringup \
  rebuild_full_navigation_050_competition_stop_candidate.launch.py \
  rviz:=false
```

该入口没有路线使能、没有初始位姿、没有 `ranger_twist_adapter_node`，也没有将导航输出接到 `/cmd_vel`。但是它经由 `rebuild_mapping.launch.py` 启动了 `ranger_base_node`，打开了 `can2` 与底盘通信。

现场随后出现异常空转和焦味，已执行物理急停和断电。启动日志确认 `ranger_base_node` 在该次 launch 中运行；没有证据表明 MPPI 或局部规划发布了真实行驶 Twist。不能据此排除底盘节点初始化、CAN 通信或既有硬件故障的影响。

## 当前禁止事项

- 不启动 `rebuild_mapping.launch.py`、`rebuild_full_navigation*.launch.py` 或任何 `start_base:=true` 的入口。
- 不解除急停以便“试试看”。
- 不发送 `/cmd_vel`、底盘 CAN 帧、错误清除帧，且不要按遥控器 `KEY1` 强制清错。
- 不把本工程中的任何历史运行命令当作复车授权。

## 硬件恢复前门槛

由具备现场设备权限的人员完成并记录：

1. 断电状态检查电机、转向电机、驱动器、电池区、线束、保险和 CAN/电源接头，确认没有变色、熔化、松脱、机械卡滞或残余焦味。
2. 确认急停电路、遥控器供电和遥控接收正常；四轮若为对称 X 形，先核对是否只是驻车锁止姿态。
3. 在空旷场地、现场监护下，仅按厂商流程完成一次遥控低速接管验证；未通过则停止并联系底盘售后。
4. 只有硬件和纯遥控均通过后，才允许进行 CAN 被动监听、底盘节点代码审计和受控节点启动测试。

## 恢复后的软件顺序

1. 不接 ROS，仅验证遥控器和电子制动。
2. 只读检查 CAN 回包，不启动 `ranger_base_node`。
3. 审计 Ranger SDK 的节点启动过程、控制模式帧、运动模式帧及默认发送行为。
4. 由现场负责人批准后，在轮组安全支撑/隔离场地执行最小化底盘节点测试；不加载导航栈、不使能路线。
5. 底盘节点稳定后，才恢复定位、局部规划静态验证，最后才进入 0.20 m/s 基线回归。
