# 组内协作与测试反馈

[返回入口](../README.md)

`第一阶段提速升级` 保存可复现的第一阶段基准。下载基准后先记录 `git rev-parse HEAD`；个人修改在新分支、新目录进行，不覆盖车上原成功目录。

```bash
cd "$HOME/car_stage1"
git status --short
git rev-parse HEAD
git switch -c codex/yourname-test-topic
```

每轮尽量只改变一个明确因素。源码或配置发生变化后，应作为新候选记录差异并维护对应的新候选清单；本阶段原清单校验失败意味着它已经不再是原封不动的基准，不能忽略失败后仍称为原版。

同一台车同一时刻仅运行一套 A–D 平台、一套导航 E，并由一位现场负责人统一安排发车。组员分别克隆和构建不等于可以同时控制同一台车。

## 每轮记录

```text
测试人／时间：
Git 分支／完整提交号：
工作目录：
本轮参数或代码改动（无改动也注明）：
A–D 配置／地图与初始化位置：
导入检查、ACTIVE CANDIDATE 和 PRECHECK 结果：
测试场景与障碍物摆放：
录包目录：
现象与大致发生时刻／位置：
是否接触障碍物、接触车身哪一侧：
是否通过本轮目标：
```

反馈时提供异常前后的 `/control/status`、`/planning/local_replan_status`、`/safety/event`、定位和 TF 等时间线。原始录包保留在车端或组内数据盘，Git 只提交代码、参数、说明和小型分析结果。

合入新改动前需说明问题、改动、离线验证、实车场景和仍未通过的项目。后续第二阶段定位优化单独开分支，不直接改写这次第一阶段的冻结运行文件。
