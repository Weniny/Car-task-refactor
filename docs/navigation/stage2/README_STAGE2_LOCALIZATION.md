## 先把三条链路分开

| 链路 | 已有证据 | 第二阶段要确认的内容 |
| --- | --- | --- |
| 连续局部运动 `camera_init → body` | 17:55 故障附近局部位姿仍连续 | IMU、激光、外参和时间戳是否产生缓慢漂移或局部异常 |
| 地图修正 `map → camera_init` | 同期有约 0.2145 m 锚定修正 | 属于正确的漂移修正还是异常匹配，何时传入控制位姿 |
| 状态保护与轨迹 | 位姿变化超限后停车，黄色历史轨迹停止累计 | 保持保护有效，解决正常全局修正与局部跟踪、异常恢复之间的不一致 |

原始 IMU 的均值不能直接作为最终导航漂移结论，地图轨迹折点也需要与连续局部运动对照。历史 TF 初始化缺失已现场解决，应与行驶中的 `position_jump` 分开记录。

## 第二阶段工作顺序

1. 固定两轮故障包和第一阶段对照包，回放地图修正前后的 TF、真实定位扫描、粒子云、IMU、局部位姿和控制状态。
2. 分项定位跳变来源，核对时间戳、坐标系、匹配质量、前端偏置估计与状态连续性判据。
3. 在独立候选中修正，记录每项参数或源码差异。真实定位异常仍应停车，异常后的恢复行为需有明确条件。
4. 先做故障帧与正常帧回归，再按现场安排复测静止定位、空场整圈和相关障碍场景。

## 怎样判断本阶段有结果

- 定位跳变有可重复的输入、明确来源和修正前后对照。
- 局部运动与全局地图修正分别检查，正常帧和真实异常帧都得到合理处理。
- 发生真实定位异常时停车，恢复行为经过验证，不靠关闭保护取得表面连续。
- 按同样导航参数完成实车对照，记录跳变次数、停顿时序、轨迹误差和人工操作。
